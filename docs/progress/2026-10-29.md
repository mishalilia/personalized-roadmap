## Target design (decided this week, no code yet)

- **A checkpoint per module.** Each question is tied to an item of the module's own checklist, and code
  rejects questions without that link.
- **Prompt-based generation, not RAG.** The curriculum is a curated list of links with no lesson text
  (a median of 75 words per section), and the linked resources keep their own licences, so there is nothing
  we may retrieve from.
- **Built so that RAG can be plugged in later.** The source of a module's context sits behind one interface,
  so for a company that supplies full lesson text, retrieval replaces it without changing the rest. This also
  answers last review's question about deploying for another company: the parser for the course format and
  the context source are the two parts that change.
- **Guarding against off-topic questions:** questions are generated once per curriculum version and reviewed
  by a team member before learners see them; an optional second model pass checks each question against the
  module.
- **Progress is gated:** a failed checkpoint blocks the next module, and "prove" becomes a real test. On
  failure the remaining path is replanned, and the learner confirms the changes.
